# Эксперименты с LLM для кредитного кабинета

Цель — сравнить 3–4 модели на целевом оборудовании и выбрать одну модель для
последующей реализации агента. Сервис остаётся общим стендом. Итоговая модель
пока не выбрана; Gemma 4 12B Agentic — кандидат. Модели не дообучаем в ходе сравнения.

## До выбора участников

Уточнить у организаторов:

- модель GPU, число GPU, VRAM каждой карты;
- CPU, объём RAM и свободного диска;
- ОС, поддержка Docker, доступность GPU из контейнера;
- можно ли заранее загрузить веса, есть ли интернет на проверке;
- сколько одновременных пользователей ожидается и какое ожидание ответа допустимо.

После этого зафиксировать 3–4 конкретных артефакта: репозиторий, revision,
имя файла, квантизацию и SHA-256. Qwen3:4b уже доступна локально как предварительный
baseline. Это не обязывает включать её в итоговое сравнение на сервере.

## Единый протокол

1. До запуска зафиксировать 12 заданий и критерии правильного ответа. Не менять
   задания под результаты конкретной модели. Промпты обозначить T01–T12.
2. Проверить 4 задания на русский контекст: исправления фактов, разделение
   историй разных людей, соблюдение границ источника, продолжение диалога.
3. Проверить 4 задания кредитного сценария на фиксированных учебных данных:
   извлечение полей, обнаружение недостающих данных, расчёт по заданным числам,
   объяснение предоставленных условий без добавления новых ставок и требований.
4. Проверить 4 задания на вызов инструментов через API: нужный инструмент,
   аргументы, отсутствие ненужного вызова, реакция на ошибку или нехватку данных.
   Всем моделям дать одинаковые схемы и фиксированные ответы инструментов.
   Для этого достаточно учебного калькулятора и локального каталога; полноценный
   агент, ML-модель и внешний веб-поиск для этого этапа не требуются.
5. Каждый тест начинать с новой историей, кроме явно многошаговых сценариев.
   Не добавлять исправляющие подсказки одной модели в основной прогон.
6. Сохранить точные сообщения, системный промпт, настройки, описание инструментов,
   фактический результат, время и оценку. Исправление ответа отдельной подсказкой
   считать отдельным экспериментом, сохранив первоначальную ошибку.
7. Выполнить по 3 независимых прогона на модель. Это небольшое прикладное сравнение,
   а не полноценный бенчмарк; статистическую значимость по нему не заявляем.

Для содержимого общей инструкции и лимита ответа использовать одинаковые значения.
Контекст ограничить общим поддерживаемым бюджетом. Для длинного текста проверить
число токенов каждого токенизатора и отсутствие обрезания. Режим thinking и все
параметры генерации записывать явно. Если применены рекомендации авторов моделей,
отметить это как отдельную конфигурацию. Достигнутый лимит токенов — обрезанный ответ,
а не автоматически ошибка понимания. Форматы чата и инструменты подавать через
штатный шаблон каждой модели.

## Что измеряем

| Направление | Что записываем |
|---|---|
| Качество | Баллы по заранее заданным критериям; ошибки и подтверждающие фрагменты |
| Надёжность | Выдуманные условия, смешение клиентов, потеря исправлений, ошибки расчётов |
| Инструменты | Правильность выбора, валидность вызова, точность аргументов, обработка ошибки |
| Скорость | Отдельно холодный старт и полное время ответа после прогрева |
| Ресурсы | Размер файла весов, пиковая RAM и VRAM; на Mac — unified memory без двойного суммирования |
| Доступность | Открытость весов, источник лицензии, регистрация/доступ, работа офлайн, совместимость runtime |

Каждый критерий оцениваем по шкале: 0 — не выполнен/противоречит условию,
1 — выполнен частично, 2 — выполнен полностью. Для каждого задания критерии
перечисляем заранее. Критические ошибки считаем отдельно от суммы баллов.
Не подменяем измеренный расход памяти размером GGUF. Не сравниваем скорость
разных серверов как свойство только модели. Если TTFT или tokens/s не измеряли,
оставляем поле пустым; по общему времени ответа их не восстанавливаем.

## Как выбираем

Сначала проверяем обязательные ограничения кейса и возможность запуска на железе.
Затем сравниваем качество, критические ошибки и вызовы инструментов. При близком
качестве учитываем скорость, память и воспроизводимость развёртывания. Не выбираем
победителя только по числу параметров или рекламному бенчмарку автора.

В итоговом заключении: конкретная модель и артефакт, результаты сравнения,
обоснование выбора, компромиссы, известные ограничения и требуемые инструменты агента.
Если испытания не выявили пригодную модель, фиксируем это и пересматриваем список.
