# Проверка предложения перед подписанием

Общая функция для разового кредита и овердрафта: [check_offer_readiness](../../credit_engine/offers.py). Применяется после выбора предложения и повторно при переходе к подписанию.

## Вызов

```python
from credit_engine import check_offer_readiness

readiness = check_offer_readiness(
    application,                 # текущая сохранённая версия заявки
    result.assessment,           # последняя сохранённая итоговая оценка
    application_state,           # состояние с selected_offer_id и latest_assessment_id
    checked_at="2026-10-20T12:05:00+03:00",
    fulfilled_condition_codes=[],
)
payload = readiness.to_dict()
```

Backend загружает заявку, оценку, выбранное предложение и сведения о выполнении условий из своего хранилища. В `fulfilled_condition_codes` передаёт только зарегистрированные им выполнения условий **этого предложения**. Например, `['guarantee_required']` после завершения моделируемого оформления поручительства. Сообщение в чате «поручительство готово» само по себе не выполняет условие.

## Что проверяется

- Заявка, её состояние, оценка и предложение относятся к одной заявке и версии.
- Оценка совпадает с `latest_assessment_id`, имеет этап `final` и содержит допустимое предложение.
- Клиент подтвердил эту версию до оценки.
- Предложение выбрано из последней оценки; срок его актуальности ещё не истёк.
- Все дополнительные условия выполнены.
- Процесс допускает переход к подписанию: состояние `offers_ready`, `conditions_pending` или `ready_to_sign`. После подписания, отмены или выдачи повторный переход блокируется.

## Результат

| `status` | Что делать |
|---|---|
| `ready_to_sign` | Разрешён переход к подписанию |
| `conditions_pending` | Показать невыполненные условия из `pending_conditions` |
| `offer_expired` | Получить новое предложение через повторную оценку |
| `reassessment_required` | Обновить рассмотрение: версия, подтверждение или оценка уже не соответствуют друг другу |
| `not_available` | Выполнить действие из `next_action` либо оставить текущий этап |
| `invalid_data` | Исправить ошибку передачи или хранения данных из `issues` |

Ответ также содержит `offer_id`, `next_action` и `issues` с `field`, `code`, `message`. `status` здесь — результат проверки готовности; он не является кредитным решением и не записывается в состояние заявки автоматически. В частности, `reassessment_required`, `not_available` и `invalid_data` не добавляют новых статусов в контракт `application_state`.

При `ready_to_sign` backend переводит заявку в одноимённое состояние; при `conditions_pending` — в ожидание условий. Функция ничего не сохраняет, не подписывает и не изменяет исходные объекты. Перед фиксацией подписания backend повторяет проверку на актуальных данных в одной транзакции с изменением состояния, чтобы изменение заявки или параллельное подписание не обошло проверку.

## Запускаемые примеры

```shell
python -m scripts.run_offer_readiness
python -m scripts.run_offer_readiness --json
```

Восемь примеров используют настоящие расчёты продуктов: готовый разовый кредит, готовый овердрафт, ожидание поручительства, выполненное поручительство, истёкший срок предложения, изменение версии, предварительное предложение и уже подписанная заявка. `--json` выводит полные входы и реальные результаты для интеграции.
