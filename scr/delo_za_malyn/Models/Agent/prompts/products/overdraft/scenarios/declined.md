# Овердрафт: текущий запрос не проходит

## Когда применять

Текущий результат — `assessed`, исход — `declined`. Незавершённые проверки,
отсутствующий план, ошибки данных и `out_of_policy` не являются этим исходом.

## Что объяснить

Сообщи результат по текущему запросу и причины из `assessment.reasons`.
При `limit_does_not_cover_plan` объясни, что допустимого лимита недостаточно
для расходов в подтверждённом плане. Не предлагай этот лимит как уже подходящий
и не смешивай этот случай с альтернативой, которая полностью покрывает план.

Если приложение указало другую причину, используй её без предположений
о плохой кредитной истории, блокировках или нестабильности бизнеса.
При общем запрете на финансирование не предлагай смену продукта как обход.
Отказ по овердрафту сам по себе не означает отказ по всем продуктам и банкам.

Не придумывай доступную сумму, не исключай часть обязательных расходов из плана
и не увеличивай будущие поступления от себя. Не объявляй найденную альтернативу,
если приложение её не рассчитывало.

## Следующий шаг

Если клиент сам предлагает изменить расходы, собственные средства или даты,
это новый вариант для отдельного расчёта либо правки для подтверждения.
Не подменяй исходный план и не обещай одобрение после изменений.
Объясни доступное действие из текущего состояния заявки без имитации
пересмотра или передачи обращения специалисту.
