# Архитектура фронтенда

Рабочий кабинет находится в `frontend/`: React + TypeScript, Vite,
Tailwind CSS и локальные компоненты shadcn/ui. Фронтенд запускается отдельно от FastAPI.
Главная `/` показывает каталог; `/cabinet` подключает профиль, заявки, денежный план,
расчёты, варианты, рассмотрение, демонстрационное оформление и ассистента к API.

`design/prototype` остаётся интерактивным референсом. `backend/static` обслуживает
старый демонстрационный кабинет `/cabinet` и тестовый чат `/chat`. Новый рабочий
интерфейс запускается на порту 5173 и не использует стили или JS из `backend/static`.

## Структура и зависимости

```text
frontend/src/
  app/                    # провайдеры, маршруты, общая оболочка
  pages/                  # композиция страниц
  features/
    products/             # каталог продуктов
      api/products.ts     # вызов API, Zod-схема и выведенные из неё типы
      model/queries.ts    # query key и настройки запроса
      ui/                 # каталог и карточка
      index.ts            # публичный экспорт функции
    applications/         # заявка, формы, план, расчёт и оформление
    assistant/            # диалог и предложения изменений
  shared/
    api/client.ts         # HTTP, таймаут, ошибки и проверка ответов
    lib/                  # форматирование и cn()
    ui/                   # исходники общих компонентов shadcn/ui
  styles/
    tokens.css            # все значения темы
    globals.css           # Tailwind, сопоставление токенов, базовые правила
```

Зависимости направлены от `app` к `pages`, далее к `features`, далее к `shared`.
Страница может напрямую использовать общие компоненты. Функции подключаются через
их `index.ts`, а координация нескольких функций происходит в странице или app.
`shared` ничего не знает о бизнес-сценариях. Автоматической проверки направлений импортов пока нет.

## Где менять внешний вид

| Изменение | Место |
|---|---|
| Цвета, фон, текст, скругление, шрифт | `src/styles/tokens.css` |
| Ширина контента и общие поля страницы | `--layout-max-width`, `--layout-gutter` в tokens |
| Вид всех кнопок или всех карточек | Соответствующий файл в `src/shared/ui` |
| Повторяющийся вариант кнопки | Новый именованный вариант в общем компоненте |
| Сетка конкретного экрана | Компонент в `pages` или `features/*/ui` |
| Данные, доступные действия и переходы | `features/*/model` и API backend |

Изменение токенов действует на все компоненты, которые их используют. Перестановка
блоков и изменение поведения выполняются в компонентах; CSS-тема не управляет логикой.
Tailwind используется для сеток и шкалы отступов. Визуальное
направление — светлая банковская стилистика:
округлая белая оболочка на серо-лавандовом фоне, фиолетовый акцент, крупные
заголовки и объёмная графика. Название и содержание проекта сохранены.
Manrope для текста и JetBrains Mono хранятся локально в `frontend/public/fonts`;
лицензии OFL — в `frontend/licenses`. Палитра, шрифты, геометрия и длительность
переходов задаются в `tokens.css`. Переключатель темы не реализован.

Горизонтальная навигация и подвал оформляются в `src/app/layout.css`; на узком
экране навигация переносится под логотип. Главная страница и адаптивный баннер
оформляются в `src/pages/home-page.css`, карточки — в
`src/features/products/ui/products-catalog.css`. Герой использует локальную
3D-иллюстрацию `public/images/finance-hero-hand.png`. В каталоге раскрываются подробные
условия из API; блок вопросов использует нативный `details` с управлением
с клавиатуры. Главная кнопка ведёт в рабочий кабинет. Его сетка и адаптивность
оформляются в `src/pages/cabinet-page.css`; поля и действия используют общие
компоненты и семантические цвета темы.

## Состояние и запросы

- TanStack Query хранит серверные данные и состояние запроса. Локальные поля,
  раскрытые панели и неподтверждённый ввод остаются в состоянии React.
- `apiRequest` выполняет HTTP и проверяет ответ Zod-схемой функции. Неожиданный
  формат становится контролируемой ошибкой; TypeScript cast не заменяет проверку.
- API-контракты берутся из реального backend и документов `BACKEND.md`, `CONTRACTS.md`,
  `OPTIONS_AND_IMPORT.md` и `LLM_CHAT_API.md`.
  Схемы frontend пока описываются вручную только для используемых методов.
- Чтение предусматривает загрузку, ошибку с повтором, пустой список и данные.
  Отмена запроса передаётся через AbortSignal. Общий таймаут — 30 секунд;
  для ответа ассистента — 120 секунд.
- Автоматические повторы отключены. Действия по заявке передают
  `base_application_version`; при конфликте 409 загружается актуальная запись.
- Результат мутации обновляет query cache и связанные чтения. Решение, статусы
  и расчёты определяет backend. Доступность редактирования зависит от состояния заявки.
- Финансовые значения остаются десятичными строками; преобразование в Number
  допустимо для отображения, но не для расчёта или изменения передаваемой суммы.

## Запуск и размещение

Инструкции находятся в [frontend/README.md](../../frontend/README.md).
При разработке Vite на `127.0.0.1:5173` проксирует `/api` на FastAPI `127.0.0.1:8000`.
Другой адрес backend задаётся `BACKEND_URL` в `frontend/.env.local`.
При сборке `VITE_API_BASE_URL` задаёт публичный префикс API (по умолчанию `/api`).

`npm run build` создаёт `frontend/dist`. На production-хосте нужно раздавать эти
файлы, проксировать `/api` в FastAPI и возвращать `index.html` для маршрутов SPA.
`npm run preview` показывает сборку локально, но не включает dev proxy. Для него
нужна сборка с доступным `VITE_API_BASE_URL` и разрешённый backend CORS origin.
Текущий Docker Compose по-прежнему запускает только backend; deployment фронтенда
ещё не настроен. Ключи модели и другие секреты никогда не помещаются в `VITE_*`.

Порядок этапов и оставшиеся задачи: [ROADMAP.md](../../frontend/docs/ROADMAP.md).
Продуктовый ориентир: [CLIENT_FORM.md](CLIENT_FORM.md) и [CLIENT_JOURNEY.md](CLIENT_JOURNEY.md).

Основы инструментов: [установка shadcn/ui в Vite](https://ui.shadcn.com/docs/installation/vite),
[тема shadcn/ui](https://ui.shadcn.com/docs/theming), [Vite](https://vite.dev/guide/).
