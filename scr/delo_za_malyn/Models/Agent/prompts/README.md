и все 14 сценариев согласованы и подключены 21 октября 2026 года.
Их копии и список файлов сохранены в
[списке согласованных сценариев](../../../../../docs/technical/drafts/SCENARIOS_REVIEW.md).
Копия общего промпта сохранена в
[черновике](../../../../../docs/technical/drafts/main-prompt.md).
Следующие редакции сначала показываются автору проекта и переносятся в рабочие
файлы после его подтверждения. Этот README модели не передаётся. Папки отражают
продукты и ситуации из текущих контрактов.


## Как заполнять

- `main.md`: роль, общий стиль, формат работы с заявкой и общие ограничения.
- `tools/web_search.md`: когда искать, как работать с источниками и ошибками поиска.
  Схема и исполняемый код инструмента остаются в `tools.py`.
- `common.md`: только особенности конкретного кредитного продукта.
- Файл сценария: только инструкции для соответствующей ситуации. Не нужно
  копировать общие правила из `main.md` и `common.md` в каждый сценарий.

Не переносите ожидаемые суммы и результаты тестовых JSON в инструкции.
Текущая заявка и настоящий результат оценки должны поступать от приложения.
Название сценария не считается решением банка и не заменяет расчёт.

## Как собирается запрос

`PromptBuilder` читает в таком порядке:

1. `main.md`.
2. `tools/web_search.md`, если инструмент доступен.
3. `products/<product>/common.md`, если указан продукт.
4. `products/<product>/scenarios/<scenario>.md`, если указан сценарий.

Пустые файлы пропускаются. Все непустые части объединяются в одно сообщение
`system`. Остальные сценарии не читаются и не попадают в контекст.
Порядок сборки не создаёт отдельного уровня привилегий для каждого файла:
инструкции должны быть согласованы между собой.

Файлы перечитываются при каждом ходе. Можно менять сценарий в существующем
диалоге: история хранит user/assistant/tool сообщения, старый system не копируется.
Разделение файлов помогает поддерживать инструкции, но размер выбранных частей
всё равно расходует контекст модели.

## Выбор и расширение

Сейчас `product` и `scenario` явно передаются из серверного кода:

```python
reply = await agent.arun(
    user_text,
    history=server_history,
    product="working_capital_loan",
    scenario="needs_information",
)
```

Автоматической маршрутизации по заявке/assessment пока нет. Клиенту не нужно
вводить команды или названия файлов. Имена из `contracts/*/scenarios/*.json`
не загружаются автоматически; в промптах нет эталонных ответов из этих файлов.

Для новой ситуации добавьте `<scenario>.md` в выбранный продукт. Для нового
продукта создайте папку с `common.md` и `scenarios/`. Названия — строчная латиница,
цифры и подчёркивание, начало с буквы, до 64 символов. Неизвестное имя, отсутствующий
файл или попытка выйти за пределы папки приводят к явной ошибке.

Для эксперимента можно передать `system_prompt="..."`: это полностью заменяет
сборку из файлов. Одновременно указывать `product/scenario` и `system_prompt`
нельзя. Корневая папка задаётся через `AGENT_PROMPTS_DIR` в общих settings.
