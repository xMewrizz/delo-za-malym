# Балльный скоринг

Модуль: [credit_engine/scoring.py](../../credit_engine/scoring.py). Версия: `demo-v1`. Скоринг оценивает кредитную историю, стабильность поступлений и концентрацию покупателей. Он не заменяет требования продукта, проверку обязательств и расчёт доступного платежа.

## 1. Баллы

Максимум — 100 баллов. Все веса и границы являются допущениями прототипа и не подтверждены статистикой дефолтов.

| Компонент | Значение | Баллы |
|---|---|---:|
| Кредитная история | `good`: история погашений без нарушений | 50 |
| | `no_history`: подтверждено отсутствие истории | 25 |
| | `minor_delinquency`: незначительные нарушения в категории симулятора | 15 |
| | `serious_delinquency`: существенные нарушения в категории симулятора | 0 |
| Колебания поступлений, `inflow_cv` | До 0,10 включительно | 30 |
| | Более 0,10, до 0,30 включительно | 20 |
| | Более 0,30, до 0,60 включительно | 10 |
| | Более 0,60 | 0 |
| Доля крупнейшего покупателя | До 25% включительно | 20 |
| | Более 25%, до 50% включительно | 10 |
| | Более 50%, до 75% включительно | 5 |
| | Более 75% | 0 |

Категория истории поступает из симулятора внешней проверки, а не из ответа LLM. Её отсутствие отличается от `no_history` и не получает баллов. Отсутствующая доля покупателя также требует уточнения. `inflow_cv` рассчитывается по [финансовой спецификации](FINANCIAL_METRICS.md).

## 2. Классы риска

| Баллы | Класс | Условие первого продукта |
|---|---|---|
| 80–100 | `low` | Без поручительства |
| 50–79 | `medium` | Поручительство до подписания |
| 0–49 | `high` | Продукт недоступен |

При `serious_delinquency` класс всегда `high`, даже если сумма баллов достигла 50. Это защитное правило продукта, а не общий запрет на финансирование. Общий запрет приходит отдельным результатом проверки.

Хорошая история даёт половину максимума; оставшиеся баллы характеризуют устойчивость операционных поступлений. Отсутствие истории получает промежуточную оценку: оно не приравнивается ни к хорошей, ни к плохой истории. При стабильных поступлениях и низкой концентрации такой бизнес получает 75 баллов и класс `medium`.

Границы 80 и 50 разделяют демонстрационные сценарии без обеспечения, с поручительством и вне условий продукта. Они не означают установленный уровень вероятности дефолта и не обосновывают реальную банковскую выдачу.

## 3. Почему используются правила

В текущем репозитории есть синтетическая заявка и демонстрационные результаты, но нет размеченной истории кредитов с наблюдаемыми погашениями. Поэтому нет основания обучать и проверять модель, прогнозирующую дефолт.

Правила позволяют воспроизводимо получить баллы, показать вклад каждого признака и проверить граничные условия. Выбранные веса выражают логику демонстрации: наибольший вес истории платежей, затем устойчивость поступлений и зависимость от одного покупателя. Эмпирического преимущества этих конкретных весов перед другими не заявляется.

Модель, обученная на метках, сгенерированных этими же правилами, воспроизводила бы нашу эвристику. Высокое совпадение с такими метками не подтверждает способность предсказывать реальные проблемы с погашением. В проекте баллы не называются обученной ML-моделью или вероятностью дефолта.

## 4. Основания для применения ML

Оценка ML требует истории заявок и выдач, признаков на момент решения, платежей и целевой метки за одинаковый горизонт наблюдения. Сведения, появившиеся после решения, не могут попадать во входные признаки. История только выданных кредитов также ограничивает выводы о заявках, по которым банк отказал.

Сравнение с правилами должно включать отдельный более поздний период проверки, качество ранжирования (например, ROC-AUC и PR-AUC), калибровку вероятностей и результат при сопоставимых ограничениях на одобрения и потери. Замена правил обоснована только при подтверждённом улучшении на независимых данных. Требования продукта, проверка доступного платежа и общие запреты остаются отдельными от модели риска.

## 5. Интерфейс

`calculate_risk_score(metrics, credit_history_category)` получает рассчитанные `FinancialMetrics` и категорию истории. Возвращает `status`, `score`, `risk_grade`, `components`, `issues`, `policy_version`.

Компонент содержит `code`, `points`, `max_points`, `message`. Статусы: `calculated`, `needs_information`, `invalid_data`. При недостатке сведений итоговые баллы и класс равны `None`; частичная сумма не используется для решения.
