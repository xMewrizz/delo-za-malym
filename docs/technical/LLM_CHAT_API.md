# Локальная проверка модели через Swagger

Это отдельный лабораторный сервер для проверки наших промптов. Основной
контейнер кабинета теперь предоставляет `/chat` и `/api/chats`; его запуск
описан в [CHAT.md](CHAT.md). Не запускайте оба сервера на порту 8000 одновременно.

На этом этапе API и модель работают на ноутбуке разработчика. Адрес тестового
API задаётся `APP_HOST` и `APP_PORT`, адрес модели — `LLM_API_BASE_URL`.
Тестовый API использует наши промпты, историю и существующий клиент модели.
Инструменты и RAG в этой ручке отключены, кредитный backend не вызывается.

## Запуск

Из корня проекта:

```sh
uv sync --frozen
uv run python -m scr.delo_za_malyn.Models.Agent.api
```

Откройте [Swagger](http://127.0.0.1:8000/docs). Для проверки самого HTTP-сервиса
есть [health](http://127.0.0.1:8000/health); он не проверяет генерацию модели.
Ollama должна быть запущена, а выбранный тег — установлен. Запуск API, открытие
Swagger и GET `/health` не загружают веса. Генерация начинается при POST `/chat`.
Первый запрос может включать время загрузки модели.

Если порт 8000 уже занят основным backend, задайте свободный `APP_PORT` в
`scr/delo_za_malyn/settings/.env` и перезапустите только тестовый API.
Оба приложения пока запускаются отдельно. Сервер привязан к `127.0.0.1`.

## Первый запрос

1. Раскройте `POST /api/v1/chat` в разделе «Диалог».
2. Нажмите **Try it out**.
3. Вставьте JSON ниже и нажмите **Execute** один раз.
4. Дождитесь ответа: текст будет в `Response body` → `response`.

```json
{
  "messages": [
    {
      "role": "user",
      "content": "Я ИП, зарегистрирован 18 месяцев назад. Пекарня по текущему адресу работает 8 месяцев. Нужно 1000000 рублей на закупку товара на 12 месяцев. Собственных средств 200000 рублей. Кратко перечисли факты, пока ничего не рассчитывай."
    }
  ],
  "product": null,
  "scenario": null
}
```

При `product=null` и `scenario=null` подключается основной промпт. Название
сценария не подсказывает модели ожидаемый исход, JSON-кейсы не подгружаются.
Для этого запроса не нужны сведения из интернета и инструменты.

В ответе есть:

- `response` — текст модели;
- `messages` — отправленная история с добавленным ответом;
- `model` — использованный тег;
- `elapsed_seconds` — длительность обработки, включая ожидание сервера модели;
- `tool_calls` — в этом тестовом режиме должен быть `0`.

Если `APP_API_KEY` заполнен, в Swagger нажмите **Authorize** и укажите его
значение для заголовка `X-API-Key`. При пустой настройке ключ для этого локального
теста не требуется. Ключ Tavily сюда не вводится.

## Как продолжить диалог

Сервер не хранит историю. Для следующего запроса скопируйте массив `messages`
из ответа в поле `messages` нового запроса и добавьте в его конец сообщение
с `role=user`. Не копируйте весь объект ответа и не добавляйте роль `system`.

Например, второе сообщение:

> У знакомого кофейня, автомобиль в залоге и была просрочка. Это его история.
> А если мне взять 800 тысяч на полтора года? Пока только объясни, что я предлагаю,
> не рассчитывай платёж и не меняй заявку.

Третье сообщение, с сохранением всей предыдущей истории:

> Перечисли актуальные факты именно о моём бизнесе. Какие сумма и срок были
> исходными, а какие обсуждались только как отдельный вариант?

Так проверяем различение возраста бизнеса и точки, своей и чужой истории,
исходного запроса и гипотетического варианта. Это проверка поведения с промптами,
а не дообучение весов. Ответы нужно оценить вручную; результаты заранее неизвестны.

Для нового диалога отправьте только первое сообщение, без предыдущей истории.
Значения `product/scenario` относятся к текущему запросу: для проверки выбранного
сценария передавайте их каждый раз, например `working_capital_loan` и `approved`.
Они подключают инструкции, но не загружают заявку или результат из JSON-примера.
Тестовая история — сообщения клиента, а не доверенные результаты проверок банка.

## Контекст и нагрузка

Для первого теста выбран контекст **4096 токенов**. В это окно входят промпт,
история, служебное оформление и генерируемый ответ. Начните с коротких 2–3 ходов
и без сценария. Файлы промптов не увеличивают доступное окно.

`LLM_CONTEXT_SIZE=4096` в `.env` задаёт параметр нашего launcher llama.cpp.
При подключении к уже работающей Ollama контекст задаётся в самой Ollama;
клиент OpenAI-совместимого API его не меняет. Смотрите
[настройку контекста Ollama](https://docs.ollama.com/context-length).

Размеры в символах не равны размерам в токенах. API проверяет `CHAT_MAX_MESSAGES`
и `CHAT_MAX_INPUT_CHARS`, но не выполняет точную токенизацию и не обрезает
историю автоматически. При превышении лимита вернётся 422. Уменьшение контекста
снижает память под кеш, но не меняет размер весов Q6.

Одновременно выполняется только один запрос. Второй получает 429. Прерывание
ожидания в браузере не гарантирует отмену генерации в Ollama. Остановка тестового
API также не выгружает модель из Ollama.

## Ошибки

- `422` — неверный JSON, недопустимая роль, сценарий или слишком длинная история.
- `401` — неверный `X-API-Key`, если настроен `APP_API_KEY`.
- `429` — предыдущий запрос ещё выполняется.
- `502` — ошибка обращения к модели, таймаут, обрезанный ответ или некорректный
  вызов инструмента. Конкретное пояснение находится в поле `detail`.

Пустое содержимое при исчерпанном лимите токенов не считается готовым ответом.
Не запускайте несколько одинаковых запросов подряд, пока не выяснена причина.
