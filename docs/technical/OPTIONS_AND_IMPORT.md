# Сравнение вариантов, денежный план и импорт

Кабинет `/cabinet` соединяет формы, ассистента и весь процесс оформления. `/chat` сохраняется как страница для проверки диалога. Основной сценарий доступен через формы без модели.

## Несколько условий кредита

`POST /api/applications/{id}/explorations`:

```json
{
  "base_application_version": 1,
  "product_id": "working_capital_loan",
  "preferences": {
    "maximum_monthly_payment": "40000.00",
    "minimum_term": 6,
    "maximum_term": 36,
    "preserve_amount": true,
    "priority": "lowest_payment"
  }
}
```

Все настройки необязательны. `requested_amount` внутри `preferences` задаёт сумму отдельного расчёта. При неизвестном сроке система проверяет сроки политики, не записывая выбранный срок в заявку. Меньшие суммы доступны при `preserve_amount: false` и подтверждённом `need.minimum_acceptable_amount`.

Каждый вариант проходит существующие правила рассмотрения. Затем применяются предпочтения клиента: комфортный платёж не заменяет банковское ограничение нагрузки. Приоритет работает внутри группы одинаковой суммы; разные суммы показываются как разные объёмы финансирования. Есть полный график, проценты, общие выплаты, условия, запас до допустимого платежа и отметки полезных вариантов.

Возвращается обычный ответ кабинета с `explorations`. Последние десять расчётов сохраняются отдельно от `application`, `result` и выбранного итогового предложения. В расчёте: `exploration_id`, `application_version`, `valid_until`, `product_id`, `result`.

Основные статусы результата: `options_ready`, `no_matching_options`, `needs_information`, `invalid_data`, `not_eligible`, `needs_checks`, `check_retry_pending`. Результат содержит `options`, `baseline`, `required_information`, `issues`, `reasons` и предпочтения. При техническом сбое можно повторить тот же запрос; симулятор проверок восстанавливается при повторе.

Для применения сохранённого варианта:

```text
POST /api/applications/{id}/explorations/{exploration_id}/apply
{"base_application_version":1,"option_id":"…","confirmed":true}
```

Backend берёт параметры из сохранённого расчёта, проверяет версию и срок актуальности. Создаётся новая версия черновика; отправленные версии сохраняются. После применения требуется отдельное подтверждение отправки и итоговое рассмотрение. Предварительный вариант нельзя использовать как итоговое предложение для подписания.

## Денежный план овердрафта

Для овердрафта запрос содержит `product_id: "overdraft"`; вместо `preferences` можно передать:

```json
{"base_application_version":1,"product_id":"overdraft","delay":{"transaction_id":"customer-001","days":7}}
```

Переносится только указанное поступление на 1–30 дней. Исходный план не меняется. Если новая дата вне периода, возвращается запрос дополнить период; предложения для неподтверждённого продления не выдаются.

По плану определяется потребность, округляется лимит и проверяется существующим модулем овердрафта. Неизвестный или недостаточный желаемый лимит не мешает предложить рассчитанный достаточный вариант, если он проходит ограничения бизнеса и продукта. Изменение суммы или плана сохраняется только после выбора и подтверждения.

В результате: `daily`, `baseline_daily`, `calculation`, `baseline`, `projected_plan`, `suggested_amount`, `limit_calculation`. Красная линия интерфейса — остаток без финансирования; зелёная — собственные деньги при расчётном использовании овердрафта. Задолженность, поступления, расходы и проценты доступны в таблице. При нарушениях показываются причины, даже если арифметический график рассчитан.

## Вспомогательный API импорта

Импорт не входит в клиентский интерфейс и основной путь оформления. Профиль и фактические показатели поступают из банковских источников. Вспомогательный API позволяет проверить разбор файла и дополнить отсутствующую историю; известные банку значения он не заменяет (`bank_data_read_only`).

Поддерживается UTF-8 CSV, включая BOM, разделитель `,` или `;`. До 150 000 символов и 120 месяцев. Заголовок:

```csv
month,operating_inflow,operating_outflow,taxes
2026-04,1000000.00,800000.00,50000.00
```

Месяцы не повторяются и завершены; нужны последние шесть полных месяцев. Суммы неотрицательные, с точкой и двумя знаками. Поступления — от деятельности, расходы — без налогов и обслуживания кредитов; налоги отдельным столбцом.

- `GET /api/applications/{id}/financials.csv` — скачать текущие показатели как шаблон.
- `POST /api/applications/{id}/imports` — `base_application_version`, `filename`, `content`.
- `POST /api/applications/{id}/imports/{import_id}/edit` — версия заявки, `base_import_revision`, исправленный список `monthly` с теми же четырьмя полями.
- `POST /api/applications/{id}/imports/{import_id}/confirm` — версия заявки, `base_import_revision` и `confirmed: true`.

Предпросмотр не меняет финансовые данные. Значения и месяцы можно исправить запросом API и повторно проверить. Правки повышают `revision`; исходные строки и SHA-256 полученного содержимого сохраняются отдельно от исправленных значений. При подтверждении требуется актуальная редакция предпросмотра. В `imports` сохраняются последние пять файлов: имя, SHA-256 содержимого, период, строки и их номера, предыдущие значения, изменения и ошибки. Статусы: `ready`, `invalid`, `applied`. Неактуальный или некорректный импорт не применяется. Подтверждение меняет только фактическую помесячную историю; будущий план остаётся отдельным. Источник сохраняется в истории приложения.

## Проверка

В кабинете загрузить пример разового кредита, нажать «Показать варианты», сравнить сроки, открыть график, подтвердить вариант и пройти оформление. Для овердрафта открыть план, рассчитать варианты, затем проверить задержку поступления; при необходимости явно продлить период. Обновить страницу и продолжить ту же заявку.
