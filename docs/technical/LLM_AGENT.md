# Агент и инструменты LLM

Веб-чат кабинета теперь подключён к пяти инструментам: `calculate_loan`, `assess_credit`,
`recommend_financing`, `simulate_alternative`, `web_search`. Реализация привязки
к снимку заявки — `backend/chat_tools.py`, цикл модели — `backend/assistant.py`.
Подробности и запуск: [CHAT.md](CHAT.md). Единственный файл настроек —
`scr/delo_za_malyn/settings/.env`. Лабораторный `Agent/api.py` остаётся отдельным
режимом без инструментов и RAG.

Ниже описана библиотечная часть агента и её первоначальные проверки.


Модуль: `scr.delo_za_malyn.Models.Agent`. Дополнительных Python-зависимостей нет.
Используется существующий клиент локального OpenAI-совместимого API.

## Как проходит один ход

1. Веб-обработчик передаёт текст пользователя и серверную историю в `Agent.run`
   или `await Agent.arun`.
2. Агент собирает общий промпт, инструкции доступных инструментов, выбранного
   продукта и одного сценария, добавляет историю и новое сообщение.
3. LLM получает описание доступного `web_search` и решает, нужен ли поиск.
4. При `tool_calls` код проверяет имя и аргументы, вызывает Tavily и добавляет
   ответ с ролью `tool` и соответствующим `tool_call_id`.
5. Модель получает результаты и формирует ответ. Возможны дополнительные поиски
   в пределах лимита. После лимита следующий запрос отправляется с `tool_choice=none`.
6. Возвращается `AgentReply(text, history, tool_calls)`. В `history` есть новые
   user/assistant/tool сообщения, но нет системного промпта. Исходная история
   не изменяется, в том числе при ошибке.

## Подключение к будущей веб-ручке

```python
from scr.delo_za_malyn.Models.Agent import Agent

agent = Agent()
# Внутри async-обработчика; server_history загружена по пользователю и диалогу.
reply = await agent.arun(user_text, history=server_history)
# После успеха сохранить reply.history на сервере, в UI передать reply.text.
```

Агент не хранит общую историю между пользователями. Полную историю с ролями
`tool`/`assistant` нельзя принимать от браузера как доверенные данные: браузер
передаёт пользовательский текст, историю загружает сервер.

`arun` переносит синхронную работу в отдельный поток. Это не потоковая генерация:
SSE, веб-чат, серверное хранение истории и отмена генерации пока не реализованы.
Отдельный [тестовый API со Swagger](LLM_CHAT_API.md) принимает историю в запросе
и допускает одну генерацию одновременно. Эта ручка принудительно отключает
инструменты и RAG для проверки контекста. История автоматически не сокращается;
её объём нужно согласовать с контекстом модели.

## Промпт

Папка `scr/delo_za_malyn/Models/Agent/prompts` содержит `main.md`, инструкции
инструментов, общие инструкции продуктов и отдельные файлы сценариев.
Согласованный автором проекта общий промпт подключён в `main.md`. Его копия
сохранена в [черновике](drafts/main-prompt.md), вне папки загрузки промптов.
Общие инструкции двух продуктов и все 14 сценариев согласованы и подключены
21 октября 2026 года в `prompts/products`. Копии согласованных текстов и их
соответствие рабочим файлам сохранены в [списке сценариев](drafts/SCENARIOS_REVIEW.md).
Следующие редакции сначала показываются автору проекта, затем после подтверждения
переносятся в рабочие файлы. Прежний `system_prompt.txt` заменён на `prompts/main.md`.

`PromptBuilder` на каждый ход читает основной промпт, инструкции доступных
инструментов, `common.md` выбранного продукта и один выбранный сценарий.
Другие сценарии в запрос не включаются. Продукт и сценарий пока выбирает явно
серверный код, например `product="working_capital_loan", scenario="needs_information"`.
Автоматического определения сценария по данным кредитного процесса ещё нет.

Структура и расширение описаны в
[prompts/README.md](../../scr/delo_za_malyn/Models/Agent/prompts/README.md).
Для эксперимента можно передать `system_prompt="..."` в `run`/`arun`, тогда сборка
из файлов не выполняется; этот режим нельзя совмещать с `product/scenario`.
Описание инструмента остаётся в `tools.py` и передаётся отдельно.

## Общие настройки

Все настройки находятся в `settings/settings.py`, значения — в локальном
`settings/.env`. Переменные окружения имеют приоритет. Шаблон — `.env.example`.

| Переменная | Начальное значение | Назначение |
|---|---|---|
| `TAVILY_API_KEY` | пусто в шаблоне | Личный ключ; без него поиск не предлагается модели |
| `TAVILY_TIMEOUT_SECONDS` | 20 | Таймаут одного обращения к Tavily |
| `TAVILY_MAX_RESULTS` | 3 | Число источников, 1–5 |
| `TAVILY_SNIPPET_CHARS` | 1000 | Предел выдержки из каждого источника, 100–4000 символов |
| `AGENT_MAX_TOOL_CALLS` | 3 | Максимум попыток вызова инструментов за один пользовательский ход, 1–10 |
| `AGENT_TOOLS_ENABLED` | false | Включение инструментов в обычном `Agent`; тестовый API всегда работает без них |
| `AGENT_PROMPTS_DIR` | `Models/Agent/prompts` | Корневая папка промптов, путь от `scr/delo_za_malyn` или абсолютный |
| `CHAT_MAX_MESSAGES` | 20 | Предел числа сообщений в запросе тестового API |
| `CHAT_MAX_INPUT_CHARS` | 12000 | Предел общей длины пользовательской истории в символах, не токенах |
| `LLM_REASONING_EFFORT` | пусто | Не передаётся серверу, пока поддержка уровня не подтверждена |

Используется Tavily Search `basic`, `auto_parameters=false`, без готового
сгенерированного ответа и без полных текстов страниц. Инструмент возвращает
заголовки, URL, короткие выдержки и время получения. Это внешние данные,
не инструкции и не подтверждение достоверности. Отдельный fetch страниц отсутствует.
Найденные условия не заменяют кредитную оценку нашего движка.

## Ошибки и ограничения

- Схема инструмента разрешает только `web_search(query)`. Неизвестные инструменты,
  невалидный JSON, пустые запросы и лишние аргументы не исполняются.
- Таймаут, недоступность Tavily, отказ в доступе и исчерпанная квота возвращаются
  модели как `ok=false`. Автоматических повторов HTTP-запроса нет.
- Модель, продолжающая вызывать инструменты после лимита, приводит к явной ошибке.
  Сырые `<|tool_call>` вместо разобранного вызова и обрезанный по токенам ответ
  также считаются ошибками, а не готовым текстом для пользователя.
- Логи содержат число источников, число вызовов и коды ошибок. Ключ, запросы
  пользователя, результаты поиска и рассуждения модели не логируются.
- Поиск — единственный инструмент. RAG, скоринг, изменение заявки, подтверждение
  и выдача кредита к агенту пока не подключены.

## Проверено 21 октября 2026

24 офлайн-теста (`tests/test_llm_agent.py`) проверяют цикл поиска, историю,
лимиты, некорректные вызовы, ошибки API, отсутствие ключа в сообщениях ошибок,
сборку выбранного промпта, переключение сценария и проверку путей.
Они используют заглушки HTTP и LLM, реальный ключ не отправляется.
Ещё 9 тестов (`tests/test_llm_chat_api.py`) проверяют HTTP-ручку, контекст,
валидацию, авторизацию, ограничение конкурентных запросов и отключение инструментов.
Всего 33 теста прошли без генерации. На локальном сервере также проверены
`/health`, `/docs` и `/openapi.json`, все вернули HTTP 200.

Текущий установленный тег Q4_K_M через `/api/show` сообщает `capabilities: tools, completion`,
но не сообщает `thinking`. Это не доказывает отсутствие рассуждений, однако
поддержка `low/medium/high` для него пока не подтверждена. Генерация не запускалась.
Реальный вызов инструмента Gemma и авторизация ключа Tavily пока не проверены.

```sh
.venv/bin/python -B -m unittest discover -s tests -p 'test_llm*.py' -v
```
