# Демонстрация кабинета

Подготовленный набор принадлежит одной компании — ООО «Север». Это связанная
история бизнеса, а не независимые тестовые сценарии. Все операции демонстрационные.

## Что посмотреть

1. **Обзор** — остаток счёта, ближайшие платежи, движение денег и заявки.
2. **Моё финансирование** — пять действующих продуктов и один кредит,
   погашенный рефинансированием.
3. **Платёжный календарь** — будущие платежи, состав долга и процентов,
   таймлайн и расчёт пеней на выбранную дату.
4. **Заявки** — готовый к подписанию оборотный кредит и инвестиционный
   кредит, для которого нужно уточнить собственный взнос.
5. **Получить финансирование** — сохранённый пример закупки со счётом PDF,
   суммой кредита и рассчитанными вариантами. Загрузка счёта не заменяет сумму кредита.
6. **С Лумой** — короткий сохранённый разговор и варианты справа. Кнопка
   новой задачи открывает отдельный запрос; дальше работает подключённая модель.
7. **Данные бизнеса** — две оплаты поставщикам с реквизитами, назначением
   и распределением между счётом и овердрафтом.

| Продукт | Что показывает пример |
|---|---|
| Оборотный кредит | Два платежа выполнены; остаток долга и будущие проценты пересчитаны |
| Инвестиционный кредит | Собственный взнос 20%, отсрочка основного долга на три месяца |
| Рефинансирование | Старый кредит закрыт, новый график учитывается без двойного долга |
| Возобновляемая линия | Выборка, оплата процентов и частичное погашение; часть лимита доступна снова |
| Овердрафт | Недостающие 35 000 ₽ оплачены поставщику; последующая выручка погасила долг и проценты |

Проценты, остатки и доступные лимиты рассчитаны штатными сервисами. В момент
подготовки набора нет просроченных платежей. Даты привязаны ко дню подготовки;
впоследствии кабинет продолжает жить по текущей дате.

## Запуск одной командой

Нужны Docker Compose и Python 3.13 / uv. Из корня репозитория:

```powershell
uv run --frozen python -m scripts.start_demo
```

Открыть **http://localhost:18007/cabinet?mode=business**. Команда собирает образ,
создаёт отдельный Docker-проект `alfa-showcase` и наполняет новый том через штатные
сервисы. При повторном запуске сохраняет операции, заявки и идентификаторы.
Рабочий `alfa_hack` и его база не меняются. Секреты из `.env` не читаются.
Манифест примеров отдаётся из того же тома, что и база: пересборка frontend для
новых UUID не нужна.

Для новой независимой демонстрации:

```powershell
uv run --frozen python -m scripts.start_demo --project alfa-showcase-fresh --port 18008
```

По умолчанию даты привязаны к сегодняшнему дню по Москве. Для воспроизводимой
проверки набора 24 октября: `--date 2026-10-24`. Для показа в другой день используйте
новый проект без фиксированной даты, чтобы не получить историческую просрочку.
Первый запуск требует интернета для Docker-образов. Существующий том без правильного
манифеста не перезаписывается: команда завершится с ошибкой.

## Лума без личного ключа

```powershell
uv run --frozen python -m scripts.start_demo --luma
```

Это настоящий локальный инференс **Qwen3-4B-Instruct-2507, Q4_K_M**, около 2,5 ГБ
весов. Точный тег: `qwen3:4b-instruct-2507-q4_K_M`, проверяемый ID манифеста
`0edcdef34593`. Короткий алиас `qwen3:4b` намеренно не используется: он указывает
на Thinking-версию, которая для этого сценария на CPU может исчерпать таймаут.
[Модель и лицензия Apache 2.0](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507).

Ollama запускается рядом с backend, веса сохраняются в `alfa_luma_models`.
`LLM_API_KEY` и `TAVILY_API_KEY` принудительно пусты. Нет вызовов Dahl и зависимости
от подарочной квоты. Поиск в интернете без Tavily недоступен; кредитный расчёт
выполняется локальным детерминированным модулем. Первый запуск скачивает модель;
дальше используются сохранённые веса. Нужна память для модели, контекста и Docker;
для стенда рекомендуется выделить Docker не менее 8 ГБ, комфортнее 12–16 ГБ.
Скорость на CPU зависит от машины; для презентации прогрейте модель до показа.

Без `--luma` кабинет работает в `CHAT_MODE=demo`: фиксированные ответы и карточки
подходят для проверки интерфейса, но это **не** свободный разговор с нейросетью.

Остановка без удаления данных:

```powershell
docker compose -p alfa-showcase -f compose.demo.yaml --profile luma down
```

## Полная проверка перед сдачей

```powershell
uv run --frozen python -m scripts.release_check --report reports/my-release --local-model-url http://127.0.0.1:11436/v1
```

Сначала запустите демо с `--luma`. Проверка последовательно выполняет все backend
тесты, эталонные финансовые контракты, сборку, lint, frontend unit и интеграцию.
Контрактные API-тесты и React-сценарии работают в разных временных базах. Затем
идут четыре явно перечисленных приёмочных сценария локальной Лумы, каждый трижды:
сбор суммы и срока, изменение только срока, защита банковских фактов и запрет
автоматического одобрения/подписания. Два последних запрета контролирует приложение
до генерации. Это приёмка конкретного маршрута, **не** оценка всего качества модели
и не статистическое сравнение с MiniMax.

Каждый этап запускается один раз. Ошибка даёт ненулевой код и остаётся в отчёте;
выборочных повторов нет. `result.json`, логи и JSONL сохраняются в новом каталоге.
Чтобы повторить проверку, укажите новый каталог, сохранив прежние результаты.

## Только генерация файла

```powershell
uv run --frozen python -m scripts.prepare_demo_cabinet --output data/showcase-new.sqlite3 --manifest data/showcase-new.json --date 2026-10-24
```

Эта низкоуровневая команда отказывается перезаписывать существующую базу. Для
показа используйте команду запуска выше: она сама связывает базу и манифест.
