# Финансовые показатели для первого продукта

Владелец: Тимофей, PM / ML Lead. Правила: `demo-v1`. Связанный продукт: [разовый кредит на оборотные цели](FIRST_PRODUCT.md).

Показатели оценивают способность заёмщика обслуживать долг. Пороги — демонстрационные допущения проекта. Решение по заявке также учитывает требования продукта, внешние проверки и скоринг.

## 1. Требования к исходным данным

Для оценки 20 октября 2026 года нужны апрель–сентябрь 2026 года: шесть последовательных полных месяцев перед месяцем оценки. Если источник содержит больше истории, выбираем нужные шесть месяцев; текущий неполный месяц исключаем. Дату оценки передаём явно, а не берём скрыто из системных часов.

| Поле контракта | Смысл и правила |
|---|---|
| `monthly[].operating_inflow` | Фактически полученные деньги от операционной деятельности; без новых кредитов и переводов между своими счетами |
| `monthly[].operating_outflow` | Фактически оплаченные операционные расходы; без налогов, процентов и основного долга по кредитам |
| `monthly[].taxes` | Фактически уплаченные налоги этого месяца |
| `existing_loans[].monthly_payment` | Полный обязательный месячный платёж по текущему кредиту: основной долг и проценты |
| `cash_balance` | Собственные деньги на дату оценки; исключаем неиспользованный кредитный лимит |
| `largest_buyer_share` | Доля крупнейшего покупателя в операционных поступлениях за те же шесть месяцев, от 0 до 1 |

Денежные поля — строки с двумя десятичными знаками в рублях. Для арифметики используем `Decimal`. Поступления, расходы, налоги, остатки и платежи неотрицательны. Отрицательный чистый поток допустим как результат вычитания и требует отдельной обработки.

Операционные поступления не равны автоматически бухгалтерской выручке, а поток после расходов и налогов — бухгалтерской прибыли. Не включаем один расход одновременно в операционные расходы, налоги и платежи по долгам.

## 2. Что рассчитываем

Обозначения: `I_m` — поступления, `O_m` — расходы, `T_m` — налоги месяца, `N = 6`.

| Показатель / внутреннее имя | Формула | Зачем нужен |
|---|---|---|
| Средние поступления / `average_monthly_inflow` | `sum(I_m) / N` | Масштаб бизнеса |
| Средние расходы / `average_monthly_outflow` | `sum(O_m) / N` | Операционная нагрузка |
| Средние налоги / `average_monthly_taxes` | `sum(T_m) / N` | Налоговая нагрузка |
| Поток месяца / `monthly_cash_flow` | `I_m − O_m − T_m` | Деньги до обслуживания долгов |
| Средний поток / `average_monthly_cash_flow` | `sum(monthly_cash_flow) / N` | Средняя способность генерировать деньги |
| Минимальный поток / `minimum_monthly_cash_flow` | `min(monthly_cash_flow)` | Слабый месяц |
| Расчётный поток / `underwriting_cash_flow` | `minimum_monthly_cash_flow` | Консервативная база первого продукта |
| Текущие платежи / `existing_monthly_debt_service` | Сумма `monthly_payment` по всем действующим долгам | Уже занятая нагрузка |
| Остаток после текущих долгов / `cash_flow_after_existing_debt` | `underwriting_cash_flow − existing_monthly_debt_service` | Деньги после существующих обязательств |
| Запас на деятельность / `operating_reserve` | `max(0, underwriting_cash_flow) × 0,30` | Часть потока, которую не разрешаем отдавать на кредиты |
| Лимит всех платежей / `total_debt_service_limit` | `max(0, underwriting_cash_flow) × 0,70` | Верхняя граница платежей по всем долгам |
| Доступный новый платёж / `available_monthly_payment` | `max(0, total_debt_service_limit − existing_monthly_debt_service)` | Лимит платежа нового кредита |
| Доля потока в поступлениях / `cash_flow_margin` | `sum(monthly_cash_flow) / sum(I_m)` | Контекст для объяснения финансов; при нулевых поступлениях — `null` |

`operating_reserve` — резерв в будущих месячных потоках, а не дополнительное списание 30% после применения коэффициента 0,70. Повторно вычитать его из доступного платежа нельзя.

Имена показателей относятся к внутреннему расчёту и не расширяют публичный `assessment` версии `0.1`.

## 3. Показатели конкретного предложения

После расчёта графика для каждого его месяца:

```text
Общие платежи = текущие платежи + платёж нового кредита
Остаток после долгов = расчётный поток − общие платежи
Доля обслуживания долга = общие платежи / расчётный поток
Покрытие платежей потоком = расчётный поток / общие платежи
```

Кандидат проходит по нагрузке, если в каждом месяце общие платежи не превышают 70% расчётного потока. Это соответствует покрытию не ниже `1 / 0,70`, приблизительно 1,43. Решение принимаем по исходному неокруглённому отношению или прямо по денежному неравенству; округлённый коэффициент 1,43 используем только для показа.

При неположительном потоке отношение не используем для одобрения. Если платежей нет, покрытие не определяем и возвращаем `null`, а не делим на ноль.

В первой версии текущие платежи консервативно сохраняем на весь срок нового кредита, даже если дата погашения старого кредита наступит раньше. Платежи с отсрочкой, переменным графиком, крупным последним погашением, действующие линии и овердрафты требуют расширения модели: их нельзя представлять как известный постоянный платёж, если он не описывает обязательства. При таких обязательствах — `out_of_policy` до добавления графиков.

## 4. Дополнительные показатели для скоринга

| Показатель | Как считаем | Как используем |
|---|---|---|
| Колебания поступлений / `inflow_cv` | Стандартное отклонение шести `I_m` с делением дисперсии на `N`, затем делим на средние поступления | Чем выше значение, тем менее равномерны поступления; балльные пороги относятся к правилам скоринга |
| Доля крупнейшего покупателя | Берём `largest_buyer_share` за выбранный период | Показывает зависимость от одного источника поступлений; не пересчитываем из агрегированных месячных сумм |
| Месяцы с неположительным потоком | Число месяцев с `I_m − O_m − T_m <= 0` | Проверяем применимость простой модели |

При нулевых средних поступлениях `inflow_cv = null`. Значение `null` в доле покупателя не означает отсутствие концентрации. Для полного скоринга нужны сведения о покупателях или подтверждённая доля; для расчёта самого денежного потока она не требуется.

Сами эти показатели ещё не задают класс `low`, `medium` или `high`. Не выдаём эвристические баллы за обученную вероятность дефолта.

## 5. Неполные данные и ограничения

| Ситуация | Обработка |
|---|---|
| Пропущен месяц, значение `null`, дубли месяцев, квартальная сумма вместо месячной | `needs_information`: указать поле и запросить исправление; не делить квартальную сумму на три без данных |
| `existing_loans: null` | Запросить сведения об обязательствах |
| `existing_loans: []` | Текущие платежи равны нулю |
| Средний поток положительный, но хотя бы один месяц неположительный | `out_of_policy`: нужна модель сезонности/календаря потоков; не сглаживать такой месяц средним |
| Средний поток неположительный | У первого продукта нет подтверждённого источника погашения; проверить общий каталог перед отказом |
| Доступный новый платёж равен нулю | У первого продукта нет доступной нагрузки; положительный остаток на счёте это не исправляет |
| Остаток долга положительный, но срок старого кредита уже истёк | Запросить актуальные сведения; не удалять долг автоматически |
| Заявленные обязательства расходятся с результатами проверки | `needs_information`: запросить сверку; не суммировать дубли и не выбирать меньший платёж |

Отрицательные значения входных денежных полей и неверный формат обрабатываются валидацией до расчёта. В интерфейсе нужно показать, что исправить. Не формируем финансовое решение по невалидным данным.

`cash_balance` и `own_funds` не прибавляем к ежемесячному потоку: это разовые средства. До включения собственных средств в задачу отдельно уточняем, какая часть остатка свободна, уже учтена в закупке и действительно может быть потрачена.

## 6. Контрольный пример

Вход: заявка `demo-001` из [examples.json](../../contracts/examples.json), оценка на 20 октября 2026 года.

| Показатель | Значение |
|---|---:|
| Средние месячные поступления | 1 000 000,00 ₽ |
| Средние месячные операционные расходы | 800 000,00 ₽ |
| Средние месячные налоги | 50 000,00 ₽ |
| Поток каждого месяца, средний и минимальный | 150 000,00 ₽ |
| Текущие платежи | 35 000,00 ₽ |
| Остаток после текущих долгов | 115 000,00 ₽ |
| Запас на деятельность, 30% потока | 45 000,00 ₽ |
| Лимит всех платежей, 70% потока | 105 000,00 ₽ |
| Доступный новый платёж | **70 000,00 ₽** |
| Доля потока в поступлениях | 15% |
| Колебания поступлений, `inflow_cv` | 0 |
| Доля крупнейшего покупателя | 25% |

Для нового кредита 1 000 000 ₽ на 18 месяцев под 24% регулярный платёж — 66 702,10 ₽. Вместе с существующим долгом клиент платит 101 702,10 ₽ в обычный месяц; остаётся 48 297,90 ₽. Доля обслуживания долга составляет примерно 67,80%, покрытие — 1,47. Последний платёж чуть выше регулярного и тоже проходит проверку.

Для 12 месяцев новый платёж — 94 559,60 ₽. Общие платежи — 129 559,60 ₽, или примерно 86,37% потока. Хотя после них остаётся 20 440,40 ₽, этого меньше установленного запаса 45 000 ₽. Поэтому исходный запрос не проходит.
