# RAG агента

Здесь будем собирать базу знаний и поиск подходящих фрагментов для модели.
Пока создана только структура: код веб-чата эту папку не читает.

## Структура

- `documents/` — проверенные описания продуктов и правил, источник и версия документа.
- `scenarios/` — обобщённые сценарии в JSON: условия применения, недостающие данные,
  подходящий инструмент и объяснение результата.
- `index/` — локальный индекс, который можно пересоздать из документов.

При подключении поиск должен возвращать несколько коротких фрагментов с источниками
и версиями. Весь корпус в системный промпт не добавляем; рабочий контекст сейчас 8192 токена.
Способ поиска и модель эмбеддингов пока не выбраны.

## Что относится к RAG

RAG подсказывает правила и нужный сценарий. Текущую заявку и состояние передаёт
приложение; платежи и доступность продукта рассчитывают инструменты. Найденный
пример не является решением по текущей заявке и не меняет её без подтверждения.
Веб-поиск остаётся отдельным инструментом для публичных актуальных сведений.

Исходные примеры: `contracts/scenarios` и `contracts/overdraft/scenarios` в корне
репозитория. Их проверочные входы и готовые ответы не следует одновременно
использовать как базу знаний и как независимый тест качества. Для базы нужны
обобщённые правила; отдельные кейсы оставляем для проверки.

## Расчёты перед подключением RAG

`assess_credit` оценивает сохранённую заявку, а не произвольную сумму из сообщения.
Для произвольного платежа веб-агенту доступен отдельный `calculate_loan`,
обёртка над существующим `credit_engine.calculate_loan`. Он принимает явные сумму,
срок и ставку, не меняет заявку и не применяет лимиты каталога. Неизвестные значения
нужно уточнять. RAG не заменяет этот расчёт. Минимальный доход нельзя получить без явного правила нагрузки,
а для бизнес-кредита нельзя автоматически подменять денежный поток личным окладом.
