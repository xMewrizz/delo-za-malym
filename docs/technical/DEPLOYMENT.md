# Стенд для проверки организаторами

VPS с 2 CPU, 4 ГБ RAM и 40 ГБ диска запускает кабинет, SQLite и HTTP-прокси. Выбранная Gemma Q4 занимает около 7,4 ГБ только весами и на этом VPS не запускается. Модель подключается через внешний совместимый API или отдельную машину. Ноутбук разработчика для работы стенда не нужен.

По разъяснению организаторов допускается сторонний API открытой модели: проверяемая версия не зависит от платного доступа, а эксперты могут заменить base URL, ключ и модель. Провайдера и конкретную модель выбираем после проверки бесплатной квоты и качества диалога. Случайный роутер разных моделей не фиксирует воспроизводимую конфигурацию.

## Настройки

Скопируйте корневой `.env.example` в `.env`. Для свободного диалога измените:

```dotenv
CHAT_MODE=model
LLM_API_BASE_URL=https://provider.example/v1
LLM_API_KEY=свой-ключ
LLM_MODEL=точный-id-открытой-модели
LLM_DOCKER_API_BASE_URL=
LLM_RESPONSE_FORMAT=json_object
LLM_CONTEXT_SIZE=8192
LLM_MAX_OUTPUT_TOKENS=2048
HTTP_TIMEOUT_SECONDS=120
AGENT_TOOLS_ENABLED=true
TAVILY_API_KEY=
```

Адрес выше — шаблон. Для API с JSON Schema используйте `LLM_RESPONSE_FORMAT=json_schema`. Для API только с JSON mode — `json_object`; backend в обоих случаях проверяет поля и действия. Требуется поддержка `tools` для вызова инструментов моделью. Без неё можно явно поставить `AGENT_TOOLS_ENABLED=false`: сбор потребности и намерение сравнения работают через JSON, ручной сценарий сохраняется. Эксперт заменяет только URL, ключ и имя совместимой модели; формат ответа настраивается при различиях провайдеров.

Внешний URL задаётся один раз в `LLM_API_BASE_URL`. `LLM_DOCKER_API_BASE_URL` нужен только если адрес из контейнера отличается, например Ollama на компьютере: `http://host.docker.internal:11434/v1`. Для Linux добавлен `host-gateway`; сам сервер модели должен принимать подключения из Docker. Его API не требуется публиковать в интернете.

Для проверки Dahl можно взять `LLM_API_BASE_URL=https://inference.dahl.global/v1` и `LLM_MODEL=MiniMaxAI/MiniMax-M2.7`, если этот ID остаётся в `/models`. По [документации](https://inference.dahl.global/docs/tokens/) новый аккаунт получает 100 млн токенов в общий пул; ключ начинает с нуля, токены нужно выделить ему вручную. Это текущая конфигурация проверки; для своего развёртывания используйте свой ключ. Генерация с `json_object` проверяется командой ниже. Использование сайта в зоне `.ru` не меняет маршрут API: запрос делает backend с VPS.

Ключ хранится только на сервере, `.env` исключён из Git и Docker-образа. Не вставляйте его в URL, frontend или примеры запросов. Не включайте платные резервные маршруты провайдера. Публичный поиск необязателен и без ключа не мешает расчётам.

## Проверка до публикации

```shell
docker compose up --build -d
docker compose exec api python -m scripts.check_llm
docker compose exec api python -m scripts.check_llm --generate
docker compose exec api python -m scripts.run_api_scenarios --base-url http://127.0.0.1:8000
```

Первая проверка LLM только читает `/models`, вторая отправляет один синтетический запрос и проверяет JSON; она расходует квоту. Успешная проверка подключения не заменяет проверку диалогов. В `/cabinet` пройти: сбор суммы/срока и подтверждение, сравнение нескольких сроков, выбор и отправку, условие поручительства, выдачу. Отдельно проверить овердрафт с планом и задержкой поступления, исправление CSV, уточнение и повтор внешней проверки. Затем обновить страницу и продолжить ту же заявку.

Один ход с инструментом обычно использует два обращения к модели: выбор инструмента и объяснение. При исчерпанной квоте нет автоматических повторов или переключения на платную модель; клиент получает понятное сообщение и может продолжить через формы. Лимит параллельных генераций — 2 на процесс, общий бюджет ожидания хода — 120 секунд по настройке.

Бесплатные лимиты проверьте в своём аккаунте перед сдачей: [Groq](https://console.groq.com/docs/rate-limits), [OpenRouter](https://openrouter.ai/docs/api/reference/limits). Наличие бесплатной модели не гарантирует доступность для вашего аккаунта и достаточную квоту для всех проверок. Для выбранного варианта зафиксируйте model ID, источник открытых весов и условия использования в `THIRD_PARTY_NOTICES.md`.

## Публикация

Направьте DNS домена на VPS и разрешите входящие 80/443. В `.env`:

```dotenv
STAND_BIND_ADDRESS=0.0.0.0
STAND_SITE=credit.example.org
STAND_HTTP_PORT=80
STAND_HTTPS_PORT=443
```

Укажите свой домен. Затем:

```shell
docker compose -f compose.yaml -f compose.stand.yaml up --build -d
```

Caddy получает и обновляет сертификат при доступном DNS и портах; кабинет открывается по `https://ваш-домен/cabinet`. API не публикуется отдельно: его порт на хосте остаётся `127.0.0.1`. Если доступен только IP, укажите `STAND_SITE=http://ваш-IP` для явного HTTP-режима. Публичный IP, DNS и настоящий сертификат проверяются на целевом VPS.

Это стенд существующего демонстрационного клиента без отдельной регистрации. Организаторам передаётся одна ссылка; модель вызывается сервером. На проверке используйте только синтетические данные.

## Сохранение и обновление

Заявки и история находятся в Docker-томе `cabinet_data`, сертификаты — в `gateway_data`. Перезапуск и пересборка их сохраняют. `docker compose down -v` удаляет тома — для обычного обновления эту команду не используйте.

Один процесс Uvicorn и SQLite достаточны для небольшого стенда. Для обновления используйте ту же команду запуска с двумя compose-файлами. После обновления проверьте `/health`, модель и сохранённую заявку. Для отката сохраните предыдущий Git commit и резервную копию SQLite; файл активной SQLite копируйте через её backup API, а не простым копированием во время записи.
