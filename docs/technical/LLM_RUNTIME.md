# Локальный LLM-модуль

Ниже описан отдельный локальный стенд Gemma. Основной кабинет подключается через корневой `.env` к совместимому API; инструкция находится в [развёртывании](DEPLOYMENT.md). Для кабинета с инструментами используется `LLM_CONTEXT_SIZE=16384` и запас ответа 4096 токенов: окно 8192 не вмещает полный начальный запрос. Настройка локальной Ollama ниже относится только к её отдельному стенду.

Python-пакет: `scr.delo_za_malyn`. Папка `delo-za-malyn` переименована в
`delo_za_malyn`, чтобы имя пакета было допустимо в обычных Python-импортах.
Импорты работают из корня репозитория без ручного изменения `sys.path`.

## Импорты и состав

```python
from scr.delo_za_malyn.Models.Llm.client import LLMClient
from scr.delo_za_malyn.settings.settings import settings
```

- `Models/Llm/client.py` — клиент OpenAI-совместимого API и обработка ошибок.
- `Models/Llm/check.py` — проверка списка моделей без генерации.
- `Models/Llm/run.py` — запуск установленного `llama-server`.
- `Models/Llm/weights` — локальный GGUF и его метаданные `source.json`.
- `Models/Agent` — цикл агента, инструмент Tavily и сборщик модульных промптов.
- `Models/Agent/api.py` — тестовый HTTP-чат со Swagger, без инструментов и RAG.
- `settings` — `settings.py`, `logging_config.py`, `.env` и `.env.example`.

## Выбранная модель

Gemma 4 12B Agentic v2 **Q4_K_M**.
Локальный файл: `scr/delo_za_malyn/Models/Llm/weights/gemma4-v2-Q4_K_M.gguf`,
7 381 381 664 байта. Файл перенесён из кеша установленной Ollama через APFS
copy-on-write; копия остаётся самостоятельным файлом, исходник Ollama сохранён.
Полный SHA-256 проверен по digest слоя весов в манифесте Ollama и записан
в `weights/source.json`. Ревизия Hugging Face для этого скачанного файла
не подтверждена и указана как `null`. Повторная загрузка не нужна.

Прежний Q6_K и журналы экспериментов сохранены локально у команды;
в репозиторий не включены. Активные настройки используют Q4_K_M.

В `settings/.env` и `.env.example` указаны:

```dotenv
LLM_MODEL=hf.co/yuxinlu1/gemma-4-12B-agentic-fable5-composer2.5-v2-3.5x-tau2-GGUF:Q4_K_M
LLM_MODEL_PATH=Models/Llm/weights/gemma4-v2-Q4_K_M.gguf
```

Относительный путь разрешается от `scr/delo_za_malyn`, независимо от текущего
каталога процесса. Переменные окружения имеют приоритет над `.env`.
В новой копии проекта создайте `.env` по `.env.example`.

## Подключение к Ollama

Адрес `LLM_API_BASE_URL=http://127.0.0.1:11434/v1` остаётся адресом локальной
Ollama. Клиент использует установленную в Ollama модель по её тегу; отдельный
GGUF нужен для другого runtime. Ключ API локальной Ollama не требуется.

Из корня проекта, в PyCharm Terminal или конфигурации запуска Python Module:

```sh
uv run python -m scr.delo_za_malyn.Models.Llm.check
```

Это служебная проверка API, без диалога, прогрева и генерации.

### Контекст и сервер с 16 ГБ RAM

Рабочее окно — **8192 токена**, `LLM_CONTEXT_SIZE=8192` в единственном
`settings/.env`. Это начальная конфигурация для теста на сервере с 16 ГБ общей
памяти; фактическое потребление всего стека и скорость CPU ещё нужно измерить.
Окно 16384 пока не включаем. Размер GGUF Q4_K_M — 7,38 ГБ, но runtime требует
дополнительной памяти для кеша, буферов и самого приложения.

У установленного GGUF `/api/show` сообщает `gemma4.context_length=262144`.
Это заявленный предел модели, а не подтверждённый рабочий режим на 16 ГБ.
В локальной Ollama текущему тегу назначен `PARAMETER num_ctx 8192`; веса,
шаблон диалога и stop-последовательности сохранены. Старый runner 4096 выгружен;
новый загрузится при следующем запросе. Генерация для проверки не запускалась.

OpenAI-совместимый API не задаёт `num_ctx` через обычные параметры запроса.
На новом хосте настройте также сам сервер Ollama: например,
`OLLAMA_CONTEXT_LENGTH=8192` в окружении запуска Ollama либо настройка окна
в приложении Ollama. Одного изменения `.env` Python-приложения недостаточно.
Проверки без генерации: `/api/show` — параметры; после пользовательского запроса
`/api/ps` — фактически выделенный `context_length`.

На локальной Ollama 0.33.1 обнаружен побочный эффект `ollama create`: вместе с
`num_ctx` он автоматически добавил `renderer=gemma4` и `parser=gemma4`. Журнал
подтверждает смену `selected=gguf_chat_template` на `selected=renderer_parser`.
Текст Go-шаблона при этом не изменился, но фактически выбран другой механизм.
Это произошло перед новым сбоем формата; причинность пока не подтверждена
повторным прогоном модели. Для текущего тега удалены только эти два поля из
локальной конфигурации манифеста, с пересчётом digest/size нового config blob.
Все слои весов, шаблона и параметров остались прежними, включая `num_ctx=8192`.
Резервная копия прежнего манифеста и конфигурации:
`~/.ollama/context-backups/20261021-164938/`. Runner выгружен без запроса генерации.
В `/api/show` снова отсутствуют принудительные `RENDERER`/`PARSER`.
В новом окружении после импорта проверяйте именно выбранный механизм в журнале,
а не только текст `TEMPLATE`. Удаление override не исправляет все возможные
ошибки модели; необходим ручной прогон.

Источники: [контекст Gemma 4 12B](https://huggingface.co/google/gemma-4-12B-it),
[настройка контекста Ollama](https://docs.ollama.com/api/openai-compatibility#setting-the-local-context-size).

## Отдельный запуск через llama.cpp

Если понадобится запуск GGUF через `llama-server`, укажите `LLAMA_SERVER_BIN`
и свободный адрес, например `LLM_API_BASE_URL=http://127.0.0.1:18080/v1`.
Тег `LLM_MODEL` в этом режиме используется как alias сервера.

```sh
uv run python -m scr.delo_za_malyn.Models.Llm.run
```

Команда выше запускает модель и создаёт нагрузку. При исправлении импортов она
не выполнялась. Самостоятельный запуск через llama.cpp ещё не проверен.

Контекст, слои GPU и sampling берутся из общих настроек запуска llama.cpp;
HTTP-клиент не меняет эти параметры уже работающей Ollama. Перед запуском
проверяются файл, сигнатура GGUF и размер из `source.json`.

## Границы текущего модуля

Клиент возвращает полный ответ (`stream=False`) или структурированные `tool_calls`.
Агент умеет выполнить `web_search` и передать результат обратно модели. История
передаётся явно между вызовами; её хранение и привязка к пользователю остаются
за будущим веб-обработчиком. Подключение описано в [LLM_AGENT.md](LLM_AGENT.md).

API кредитного процесса уже есть в `backend`. Для проверки модели добавлен
отдельный [HTTP-чат со Swagger](LLM_CHAT_API.md). Он не подключён к кредитному
процессу; пользовательского веб-чата, потоковой выдачи, RAG и кредитных инструментов
пока нет. Терминального чата нет.

`.env`, GGUF, Python-кеш и логи исключены из Git. В репозиторий попадают код,
`.env.example` и метаданные весов, сам файл модели остаётся локально.
