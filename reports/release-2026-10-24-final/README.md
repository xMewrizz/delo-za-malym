## 2. Трасса решения

`result.decision_trace` сохраняется на backend вместе с каждым новым рассмотрением,
включая предварительное. Пять этапов связаны с ID рассмотрения, версией заявки,
версией правил и временем. Баллы и значения берутся из **того же результата**
финансового и скорингового модулей. Историческое решение не пересчитывается по
изменившемуся профилю.

В живой заявке показаны история данных, компоненты риска, 70% расчётного потока
минус текущие обязательства, ограничения выбранного продукта и итоговые причины.
Для овердрафта отображаются ограничения по обороту и нагрузке; для рефинансирования
исключены заменяемые платежи; для кредитной линии отдельно поясняется резерв нагрузки.
Если исходных сведений не хватает, невыполненные этапы не получают выдуманных чисел.

Проверены сохранность после перезапуска, отказ при неполных сведениях, все пять
продуктов в наполненной базе и отмена после исторического одобрения. UI проверен
на 1440 и 390 px: нет горизонтального переполнения; минимальный измеренный контраст
нового блока 8,15:1 в тёмной теме и 5,24:1 в светлой. Старые записи без трассы сохраняют прежнюю историю этапов.

загрузка Docker-образов и весов требует интернета. Рекомендовано выделить Docker
12–16 ГБ RAM. Поиск Tavily без отдельного ключа недоступен.
