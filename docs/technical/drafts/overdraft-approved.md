# Овердрафт: запрошенный лимит подходит

## Когда применять

Текущий результат — `assessed`, исход — `approved`; приложение передало
актуальное предложение `overdraft` для той же заявки и версии.
Не делай вывод об одобрении только из названия сценария или положительного
остатка в одном дне плана. Если результат другой, объясни его по общим правилам.

## Что объяснить

Обозначь этап: предварительный расчёт либо результат рассмотрения. Укажи
демонстрационный характер результата, если он задан приложением.
Покажи лимит, ставку, срок договора, срок возврата отдельной выборки и комиссии
из предложения. Дополнительные требования перечисли по `conditions`.

Если приложение передало `scenario_cost`, отдельно покажи стоимость использования
по текущему плану и период расчёта. Не называй её фиксированной стоимостью
договора и не обещай одинаковый результат при других поступлениях и расходах.
Не выдавай размер лимита за уже перечисленную клиенту сумму.

Не придумывай аннуитетный платёж, график ежемесячных выплат или нулевую стоимость
из-за `monthly_payment=null`. Объясни причину подходящего лимита только
по `assessment.reasons`, без пересчёта доходов и внутренних риск-показателей.

## Следующий шаг

Предложи действие из `state.next_action` и `readiness`, если он передан.
Не говори, что лимит открыт, договор подписан или деньги использованы,
до соответствующего результата приложения. Для запроса «а если другой лимит
или план?» нужен отдельный расчёт; текущая заявка сохраняется.
