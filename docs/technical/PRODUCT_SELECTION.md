# Выбор между разовым кредитом и овердрафтом

Модуль: [recommend_financing](../../credit_engine/selection.py). Подбирает механику и рассчитывает предварительные варианты, сохраняя исходную заявку. Итоговое рассмотрение остаётся отдельным этапом.

## Логика выбора

| Задача клиента | Основной вариант | Что уточняется |
|---|---|---|
| Перекрыть расходы до конкретных поступлений | Овердрафт | План поступлений и расходов, остаток денег, погашение каждой выборки |
| Получить сумму и возвращать постепенно из выручки | Разовый кредит | Сумма и желаемый срок, доступный ежемесячный платёж |
| Задача пока неясна, продукт не выбран | Вопрос о способе возврата | До ожидаемого поступления или постепенно из выручки |
| Продукт уже выбран, способ возврата не указан | Сначала выбранный продукт | Недостающие параметры его расчёта |

Новое необязательное поле `need.financing_pattern`: `cash_gap`, `gradual_repayment` или `null`. Его заполняет форма либо ассистент после подтверждения клиента. Регулярность расходов сама по себе не определяет продукт: `recurring: true` не означает автоматический выбор овердрафта.

Каждый подходящий кандидат проходит существующий модуль оценки: финансы, внешние проверки, риск, ограничения продукта и расчёт условий. Для сравнения используется копия заявки без ограничения на предпочитаемый продукт; все исходные значения и подтверждённая заявка сохраняются. Расчёты имеют этап `preliminary`.

Если основная механика требует уточнений, спрашиваем их. Например, при кассовом разрыве запрашиваем план даже тогда, когда разовый кредит уже проходит по финансовым показателям. Рассчитанный кредит при этом виден как альтернатива.

Если основной продукт исключён, другой может быть рекомендован после своих проверок. Например, допустимого лимита овердрафта недостаточно, но разовый кредит покрывает расходы и проходит по платежам. Если срок кредита не указан, сначала запрашиваем его. При наличии рассчитанного разрыва сумма альтернативного кредита должна его покрывать; подтверждение меньшей суммы не заменяет согласованный план расходов.

Общий запрет финансирования исключает оба продукта. Если проверенный план показывает отсутствие потребности в заёмных деньгах, другой кредит вместо овердрафта не предлагается. Неизвестные сроки и поступления не подставляются автоматически.

## Ответ

`status`: `recommendations_ready`, `needs_information`, `not_eligible`, `invalid_data`, `needs_checks` или `check_retry_pending`.

- `recommended_product_id` — основной рекомендуемый продукт, если данных достаточно и он прошёл проверки.
- `required_information` — вопросы с `field`, `code`, `question`.
- `candidates` — два продукта с ролью `primary` / `alternative`, причинами, допустимыми `offers`, необходимыми уточнениями и `eligibility`.
- `evaluation` внутри кандидата — полный результат его финансовой оценки. **Карточки строятся по `candidate.offers` и `candidate.eligibility`**: дополнительная проверка достаточности суммы для плана может исключить предложение из карточек, сохранив исходный расчёт для объяснения.

Стоимость кредита имеет `cost_basis: full_term`, овердрафта — `planned_operations`. Проценты за весь кредит и проценты за короткий план не используются как взаимозаменяемые оценки дешевизны. Порядок определяется задачей и доступностью продукта; приоритет клиента учитывается существующим расчётом альтернатив внутри разового кредита.

## Подключение к кабинету

`POST /api/applications/{id}/recommendations` с телом:

```json
{"base_application_version": 1}
```

Ответ — обычный объект заявки с новым полем `recommendation`. Подбор не заменяет `result`, итоговое предложение, выбранный вариант или состояние заявки. Сведения сохраняются и доступны через `GET`.

При `check_retry_pending` или `needs_checks` повторно вызывается этот же метод подбора; отправлять заявку ради повтора проверки не требуется. В демонстрационном сценарии временного сбоя повтор восстанавливает проверку.

После выбора клиентом карточки:

1. Через обычное подтверждение и `PATCH` применить продукт, сумму и срок выбранного варианта. Для овердрафта `term_months` — `null`.
2. Получить новую версию заявки; прежняя рекомендация сбрасывается.
3. Подтвердить отправку через `/submit`, получить итоговую оценку и продолжить оформление.

Предложения из рекомендаций нельзя подписать напрямую. При изменении заявки, выборе другого продукта и повторном рассмотрении используются обычные правила версий и подтверждения.

## Примеры

```shell
python -m scripts.run_financing_selection
python -m scripts.run_financing_selection --json
```

Девять примеров: уточнение задачи, постепенный возврат, короткий разрыв, отсутствие плана, два рассчитанных продукта, кредит вместо недостаточного лимита, уточнение срока альтернативы, общий запрет и отсутствие разрыва. `--json` выводит входы и реальные рассчитанные ответы.
