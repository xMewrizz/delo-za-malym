# Фронтенд

`frontend/` — React + TypeScript + Vite, React Router, TanStack Query, Zod, Tailwind и Radix. Главная `/` — обзорный лендинг; `/project` — устройство проекта и ссылки на существующие документы. `/cabinet` открывает обзор бизнеса, а `?mode=business|manual|assistant|applications|portfolio|calendar` выбирает профиль, один из двух способов подбора, заявки, полученные продукты или календарь. Docker собирает статические файлы и FastAPI раздаёт их с того же адреса, что и `/api`. Тестовый чат `/chat` сохранён отдельно.

## Модули

- `app` — маршруты, провайдеры и оболочка.
- `pages` — сборка экранов и координация функций.
- `pages/cabinet-navigation` — боковая навигация и раскрываемое меню на узком экране; два режима подбора объединены в одном разделе.
- `pages/cabinet-insights` — обзор, профиль и полученное финансирование из текущих API.
- `features/calendar/api` — общий Zod-контракт календаря и фильтрация событий по конкретному продукту. `product=loan:<loan_id>` выбирает кредит банковского профиля, `product=app:<application_id>` — продукт, полученный через кабинет. Без параметра видны все продукты. К фильтру можно перейти из карточки продукта; смена фильтра не сбрасывает выбранный месяц и не забирает фокус.
- `features/products` — обзор продуктов на публичном лендинге: назначение, механика возврата, переход к подбору. Суммы, лимиты, ставки и числовые сроки на лендинге не показываются, включая раскрываемые подробности.
- `features/applications` — данные бизнеса, потребность, сравнение, план и оформление.
- `features/assistant` — сообщения, уточнения, изменения из разговора и предпросмотр.
- `shared` — HTTP-клиент, форматирование и общие элементы интерфейса.

Серверные данные находятся в TanStack Query, ответы проверяются через Zod. Расчёты и решение выполняются на backend; суммы передаются десятичными строками.

## Черновики и подтверждение

Самостоятельный подбор и ассистент создают разные заявки. Их идентификаторы и несохранённый ввод восстанавливаются из локального хранилища. Подтверждённые данные, история диалога и этапы заявки сохраняются на сервере.

В самостоятельном подборе кнопка продолжения сохраняет потребность и переводит к денежному плану или вариантам. Перед расчётом показано резюме запроса; повторные параметры спрятаны в «Настроить сравнение». Для кассового разрыва без явно выбранного продукта сразу рассчитывается овердрафт. Потребность и план можно открыть для исправления, заявка отправляется отдельным действием.

В разделе получения финансирования сводка банковского профиля над формой не отображается: эти сведения доступны в «Данных бизнеса». Сервер продолжает учитывать остаток, историю и действующие обязательства в расчёте. В режиме оформления заявки сводка сохранена для проверки контекста.

Предложение ассистента отображается в рабочей области сразу после ответа. `/proposals/{id}/preview` считает его на копии; приложение не меняется до подтверждения. Карточки уточнений приходят из API и отвечают через `/clarifications/{id}/answer`, без дополнительного вызова модели.

Изменившиеся сумма, задача и срок получают короткую подсветку при появлении; во время запроса показано ожидание ответа/пересчёта. Это обновление по полученному структурированному ответу, не имитация потокового ответа по токенам. `prefers-reduced-motion` отключает движение. Ранее реализованные правила версии, независимых черновиков и подтверждения сохранены.

После подтверждения данных сервер создаёт варианты. Выбор через `/explorations/{id}/apply` переводит пользователя в «Заявки»; отправка требует отдельного подтверждения. Предварительные варианты не подменяют итоговое банковское решение.

Мутации передают версии заявки и диалога. При 409 загружаются актуальные данные; действие автоматически не повторяется. Поздний ответ ассистента обновляет только его черновик.

## Документы и денежный график

В обоих сценариях встроена загрузка PDF-счёта. Карточка показывает извлечённые сумму и дату, оригинал и строки источника. Изменение отличающихся значений требует подтверждения; покупка не превращается в сумму кредита автоматически. В диалоге документ дополняет предложение ассистента, которое затем подтверждается вместе с остальными данными.

В вариантах разового кредита раскрывается календарь платежей. При наличии денежного плана рассчитывается дневной остаток с выдачей и погашением кредита; перенос поступления сравнивается с исходным сценарием. График загружается по требованию. Для разового кредита денежный план необязателен, для овердрафта нужен для расчёта лимита.

## Оформление и запуск

Тема задана в `src/styles/tokens.css`, общие элементы — в `src/shared/ui`. Manrope и JetBrains Mono поставляются локально, лицензии находятся в `frontend/licenses`. Интерфейс предусматривает мобильную компоновку и `prefers-reduced-motion`.

Брендовые SVG и favicon из утверждённого комплекта находятся в `public/brand`. Палитра: purple `#7544D8`, mint `#A6E8CD`, ink `#202124`, lavender `#F5F1FC`. Контурный логотип не зависит от шрифтов; Arial из комплекта не распространяется. Подробности — `frontend/docs/INTERFACE.md`.

`public/project-docs` содержит публичный снимок README, MVP, архитектуры, API и сценариев; при изменении соответствующих документов снимок обновляется вместе с интерфейсом. Секретные конфигурации туда не копируются. `/docs` открывает интерактивный API; Vite проксирует его и `/openapi.json` к backend.

[Запуск и тесты](../../frontend/README.md) · [Готовые функции и ограничения](../../frontend/docs/ROADMAP.md).

Готовые предложения показаны перед закрытыми настройками сравнения. Проверка задержки поступления — дополнительное действие по сохранённому денежному плану. PDF-счёт используется как будущий расход или подтверждение покупки; переноса итога в сумму кредита в интерфейсе нет. У суммы и даты оплаты доступны ссылки на источник.
