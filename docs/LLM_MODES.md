# Два режима Лумы

Основная локальная модель команды — Gemma 4 12B Agentic v2 Q4_K_M. На VPS публикуем кабинет с API Dahl. Внешний API и локальная модель используют один банковский модуль; модель не определяет одобрение, ставки и суммы самостоятельно.

## Локально: Gemma в Docker

Из корня проекта:

```shell
uv run --frozen python -m scripts.gemma_weights
uv run --frozen python -m scripts.start_demo --provider local
```

Кабинет: `http://localhost:18007`. Ollama: `http://localhost:11437/v1`, модель `alfa-gemma-q4`. Первый запуск импортирует уже скачанный GGUF; повторно тянуть веса из Hugging Face внутри контейнера не нужно. Модель хранится в отдельном Docker-томе. Для повторной проверки локального файла: `uv run --frozen python -m scripts.gemma_weights --check`.

Полный SHA-256: `0b9506cab36f7f818e34f9c0f5a3d6568d0b37100f3a3e1092e2eec3c4c96791`. Размер: 7 381 381 664 байта. Источник: [репозиторий весов команды](https://huggingface.co/yuxinlu1/gemma-4-12B-agentic-fable5-composer2.5-v2-3.5x-tau2-GGUF).

На компьютере с NVIDIA и настроенной поддержкой GPU в Docker:

```shell
uv run --frozen python -m scripts.start_demo --provider local --gpu
```

Это включает `compose.gemma-gpu.yaml`. CPU-режим не требует NVIDIA. Контекст — 16 384 токена, ответ — до 4096. Размер GGUF не равен общей памяти процесса: нужны кеш контекста и буферы. Замер RAM/VRAM, скорости и полноценные диалоги выполняются на конкретной машине; прежние прогоны сокомандника не заменяют приёмку нового окружения. Системные сведения об интегрированной Radeon не подтверждают GPU-ускорение этого Docker-профиля.

## API: локально или на VPS

В серверном `.env` по образцу `.env.example` укажите:

```dotenv
CHAT_MODE=model
LLM_API_BASE_URL=<OpenAI-совместимый URL Dahl>
LLM_MODEL=<точный ID модели у провайдера>
LLM_API_KEY=<ключ провайдера>
LLM_RESPONSE_FORMAT=json_object
```

Не коммитьте `.env` и не передавайте ключ через frontend. Для наполненного локального кабинета:

```shell
uv run --frozen python -m scripts.start_demo --provider api --env-file .env
```

Для VPS:

```shell
docker compose --env-file .env -f compose.yaml -f compose.api.yaml -f compose.stand.yaml up --build -d
```

В составе VPS нет Ollama, контейнера импорта, модельного тома и GGUF. Веса исключены из Docker build context. Адрес сайта и доступ задаются настройками стенда. Настоящее развёртывание и проверка Dahl выполняются отдельно при наличии сервера и его конфигурации.

## Переключение с сохранением данных

Используйте одно имя `--project` и не удаляйте тома. Сначала остановите предыдущий состав через тот же набор Compose-файлов с командой `down` **без `-v`**, затем запустите нужный режим. Так локальная модель не останется занимать память при переходе на API, а база заявок сохранится.

Пример остановки локального демо:

```shell
docker compose --env-file /dev/null -p alfa-showcase -f compose.demo.yaml -f compose.gemma.yaml down
```

На Windows вместо `/dev/null` используется `NUL`. Останавливайте только свой Docker-проект. Обычный `start_demo` не удаляет базу и не переинициализирует наполненное демо. `--no-build` позволяет использовать уже собранный образ приложения.

## Что уже тестировали

- Прежние эксперименты Gemma, включая вызов инструмента расчёта, сохранены в локальных журналах команды; они не заменяют проверку текущей машины.
- Qwen ранее прошёл отдельную ограниченную приёмку 12/12; маршрут сохранён командой `start_demo --luma`. Это не сравнение качества с Gemma. [Текущие проверки и команды](CHECKS.md).
- Новый локальный профиль Gemma должен пройти отдельную приёмку после импорта и запуска. API Dahl проверяется отдельно с конфигурацией опубликованного стенда.

Команда полного прогона с Gemma (используйте новый каталог отчёта):

```shell
uv run --frozen python -m scripts.release_check --report reports/gemma-local-new-run --local-model-url http://127.0.0.1:11437/v1 --local-model alfa-gemma-q4
```

Этот прогон не запускался автоматически при скачивании весов. Он включает проверки проекта и ограниченную приёмку Лумы; свободные диалоги команды проверяются дополнительно.
